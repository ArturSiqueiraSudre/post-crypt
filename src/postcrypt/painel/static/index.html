Quem autorizou esta varredura

O Post-Crypt verifica os serviços que você listar e responde, para cada um, se o tráfego gravado hoje pode ser aberto no futuro, se a cifra é forte e se o certificado está em dia. Só varra sistemas que você tem permissão para testar: este registro sai junto com o resultado.

Um serviço é um endereço e uma porta, como o site da empresa (porta 443) ou a VPN. O Post-Crypt só conversa com o que estiver nesta lista. Não sabe o que preencher? Veja o guia.

        O arquivo de escopo é a lista dos serviços que o Post-Crypt tem permissão para verificar, junto com o nome de quem autorizou. Sem ele não há varredura: a ferramenta nunca procura sistemas por conta própria.

        Jeito mais fácil: montar pelo painel

        Você não precisa escrever o arquivo. As etapas Autorização e Serviços montam e conferem tudo para você.

        1. Na etapa Autorização, diga quem autorizou. Nome e cargo da pessoa que permitiu o teste e a data da autorização. Se existir um documento (termo, e-mail, chamado), anote no campo de referência.
        2. Na etapa Serviços, adicione um serviço por linha. Cada linha é um endereço e uma porta. Use o botão Adicionar serviço para incluir mais.
        3. Clique em Salvar escopo. O painel confere os dados e baixa o arquivo escopo.yaml para o seu computador.
        4. Na próxima vez, clique em Abrir arquivo de escopo. As etapas são preenchidas de novo com o que você salvou, prontas para varrer.

        Ir para a etapa Serviços

        Se preferir escrever à mão

        O arquivo é um texto simples com a extensão .yaml. Baixe o modelo, abra no Bloco de Notas e troque os exemplos pelos seus dados.

        # Arquivo de escopo do Post-Crypt.
# Linhas que começam com # são anotações: pode apagar.

authorization:
  by: "Maria Souza (gerente de TI)"         # quem autorizou a varredura
  date: 2026-11-11                          # quando autorizou: ano-mês-dia
  reference: "Termo de escopo nº 01/2026"   # opcional

targets:
  - host: www.suaempresa.com.br   # endereço, sem https://
    port: 443
    label: Site da empresa

  - host: vpn.suaempresa.com.br
    port: 443
    label: Portal VPN

  - host: 10.0.10.25              # endereço IP também vale
    port: 8443
    label: Sistema do fornecedor
    owner: third_party            # o serviço é de um fornecedor
    sni: api.fornecedor.com.br    # nome no certificado, quando o endereço é um IP

        • Use espaços, nunca a tecla Tab. O recuo de dois espaços no começo das linhas faz parte do formato.
        • Cada serviço começa com um traço (- host:) e as outras linhas dele ficam alinhadas logo abaixo.
        • Salve como escopo.yaml. No Bloco de Notas, escolha "Todos os arquivos" em Tipo e a codificação UTF-8.
        • Confira antes de usar. Abra o arquivo na etapa Serviços com Abrir arquivo de escopo: se algo estiver errado, o painel diz o quê.

        Como achar o endereço e a porta

        Olhe o endereço que você digita para acessar o sistema. O que vem depois de https:// e antes da primeira barra é o endereço. Se houver dois-pontos e um número, esse número é a porta; se não houver, a porta é 443.

        Você acessa porEndereçoPorta
        https://www.suaempresa.com.br/loginwww.suaempresa.com.br443
        https://sistema.suaempresa.com.br:8443/painelsistema.suaempresa.com.br8443
        https://10.0.10.25:844310.0.10.258443

        Para VPN, e-mail e sistemas de fornecedor, peça o endereço e a porta à equipe de TI ou ao fornecedor. Hoje o Post-Crypt verifica serviços que falam TLS direto na porta, como sites, APIs e portais de VPN por navegador. Um serviço de outro tipo aparece no resultado como "Revisar".

        O que o Post-Crypt recusa, de propósito

        Cada serviço precisa aparecer na lista com endereço e porta próprios. Isso garante que só o que foi autorizado seja contatado. Um arquivo com qualquer item abaixo é recusado inteiro, e nenhuma varredura começa.

        • Faixa de endereços. Liste cada servidor em uma linha própria. 
          - host: 10.0.0.0/24
  port: 443
        • Curinga. Escreva o nome completo de cada serviço. 
          - host: "*.suaempresa.com.br"
  port: 443
        • Endereço com https:// ou barras. Use só o nome do servidor. 
          - host: https://www.suaempresa.com.br
  port: 443
        • Serviço sem porta. O endereço e a porta são sempre obrigatórios. 
          - host: www.suaempresa.com.br
        • Porta entre aspas ou fora de 1 a 65535. Escreva só o número. 
          - host: www.suaempresa.com.br
  port: "443"
        • Campo que não existe. Só valem os campos da tabela acima. 
          - host: www.suaempresa.com.br
  port: 443
  senha: abc123

        Também são recusados o mesmo endereço e porta listados duas vezes e o arquivo sem o bloco de autorização.

        Mensagens de erro e como resolver

        Preencha quem autorizou a varredura e a data da autorização
        Falta o nome ou a data no bloco authorization. Os dois são obrigatórios.
        A data da autorização está incompleta
        Escreva a data como ano-mês-dia, com quatro dígitos no ano: 2026-11-11.
        Adicione pelo menos um serviço
        A lista targets está vazia ou não existe.
        Parece uma faixa ou um curinga
        O endereço tem barra, asterisco ou interrogação. Tire o https:// e liste cada servidor separadamente.
        Endereço inválido
        O endereço tem espaço, acento ou outro símbolo que não vale em nomes de servidor.
        Porta inválida
        A porta precisa ser um número de 1 a 65535, sem aspas.
        Serviço repetido
        O mesmo endereço e a mesma porta aparecem duas vezes. Apague uma das linhas.
        Campos desconhecidos
        Há um campo com nome errado ou que não existe. Confira a grafia com a tabela de campos.
        O arquivo não é um YAML válido
        Quase sempre é recuo: use dois espaços (nunca Tab) e mantenha as linhas de cada serviço alinhadas. Um asterisco no endereço também causa esse erro.
